# DeepAgents Code 차세대 Coding-Agent Harness 심층 연구·설계·개발계획·실행계획 요청

당신은 이번 작업에서 단순한 기술 조사자나 문서 작성자가 아니다.

당신의 역할은 다음을 모두 수행하는 **Principal AI Agent Architect + Coding-Agent Researcher + Staff Software Engineer + Implementation Planner**이다.

최종 목표는 최신 Coding Agent / Agent Harness 기술을 충분히 조사한 뒤, 현재 우리가 개발 중인 **DeepAgents Code 기반 Coding Assistant**에 실제로 반영할 가치가 있는 기술을 선별하고, 모순 없는 목표 아키텍처와 상세 설계, 개발계획, 실행계획, 검증계획까지 완성한 후 모든 결과물을 ZIP 파일로 패키징하여 사용자가 바로 다운로드할 수 있게 만드는 것이다.

단순 조사 보고서에서 끝내지 마라.

반드시 아래 전체 사이클을 끝까지 완수해야 한다.

---

# 0. 최종 목표

다음 전체 흐름을 완수한다.

```text

    ↓

    ↓

    ↓

    ↓

    ↓
채택 / 부분 채택 / 보류 / 제외 결정
    ↓
통합 Target Architecture
    ↓
상세 설계
    ↓
개발 단계 및 구현 순서
    ↓
파일/모듈 단위 개발계획
    ↓
Migration / Rollout 계획
    ↓
```

최종 결과는 **다른 하위 모델이나 coding agent가 추가 설명 없이 그대로 구현을 시작할 수 있는 수준**이어야 한다.

# 4. 핵심 연구 질문

각 프로젝트를 단순 기능 목록으로 작성하지 마라.

반드시 다음 질문에 답하라.

## 4.1 Agent Core

- Agent loop는 어떻게 구성되어 있는가?
- reasoning → tool → observation loop는 일반적인 ReAct와 무엇이 다른가?
- runtime이 강제하는 invariant가 있는가?
- 모델에게 맡기는 부분과 deterministic runtime이 담당하는 부분은 무엇인가?

---

## 4.2 Model Portability

특히 중요하다.

우리의 문제의식은:

> Claude Code에 Claude가 아닌 모델을 붙이면 API 자체는 호출되지만 해당 모델의 실제 잠재 성능이 충분히 나오지 않는 경우가 있다.

따라서 각 agent에 대해 다음을 확인한다.

```text
Provider abstraction
Protocol abstraction
Tool-call normalization
Reasoning normalization
Message normalization
Thinking handling
Role compatibility
Tool-result compatibility
Prompt adaptation
Model capability detection
Per-model tuning
Fallback
Routing
Multi-model orchestration
```

특히 다음 모델/계열을 고려한다.

- Claude
- GPT 계열
- Gemini
- Qwen
- Kimi
- GLM
- DeepSeek
- MiniMax
- Mistral
- local models
- OpenRouter 제공 모델

중요:

모델별로 거대한 별도 prompt를 하드코딩하는 방식이 아니라,

```text
Common Harness
+
Capability Normalization
+
Thin Model-Specific Adaptation
```

형태가 가능한지 검토한다.

# 13. Self-Improving

“agent가 자기 prompt를 바꾼다” 정도로 정의하지 마라.

다음을 각각 분리한다.

```text
Failure → lesson extraction

Lesson → memory

Repeated lesson → skill candidate

Skill candidate → evaluation

Evaluation → promoted skill

Old skill → decay

Duplicate skill → merge

Bad skill → rollback

Human review feedback → policy improvement
```

Self-improvement에 반드시 governance를 둔다.

agent가 검증 없이 자기 core prompt를 계속 수정하는 구조는 피한다.

```text

→ Agent ↔ Tool / Resource
```

다음을 검토한다.

- A2A remote agent

```text

   ↓
```


까지 설명한다.

# 43. 마지막 요구

이번 작업의 핵심 질문은:

> “어떤 agent가 가장 좋은가?”

가 아니다.

핵심 질문은:

> “2026년 현재 가장 발전된 Coding-Agent/Harness 기술 중 무엇이 실제로 우리 DeepAgents Code를 더 뛰어난 모델-독립적 Coding Assistant로 만들 수 있으며, 그것을 최소한의 불필요한 복잡성으로 어떻게 통합 구현할 것인가?”

이다.

조사 결과에서 기존 계획보다 더 좋은 구조가 발견되면 기존 설계를 유지하려고 하지 말고 수정하라.

최종 결과는 연구 보고서가 아니라 **실제 차세대 DeepAgents Code 구현을 시작하기 위한 engineering package**여야 한다.
