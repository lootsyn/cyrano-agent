## 실행 순서

1. 입력 artifact와 선행 evidence의 digest·실행 상태를 확인한다. 문서만 있는 선행 작업을 통과로 취급하지 않는다.
2. 구현 계획에 public API, 변경 경로, 불변 조건, positive/negative test, 외부 side effect, rollback을 적는다. 독립 reviewer의 mandatory finding을 먼저 해결한다.
3. 아래 acceptance ID마다 재현 가능한 거부/정상 테스트를 먼저 작성한다. 현재 기반 unit 사례를 복사해 product 통합 사례가 된 것처럼 이름만 바꾸지 않는다.
4. 명세의 결정적 부분부터 구현하고 실제 provider/host 연결은 명시 port로 결합한다. 미지원 기능은 typed unsupported로 반환한다.
5. timeout·cancel·late result·partial startup·duplicate request·scope mismatch를 포함해 구현한다. 실패를 success/empty default로 감추지 않는다.
6. 작성한 targeted test와 schema/문서/기반 회귀/품질 검사를 실행한다. 실제 runtime 또는 paid model이 필요한 부분은 별도 허가가 없으면 not_run으로 보고한다.
7. 담당 설계·schema·config·fixture·문서 라우터를 같은 변경에서 갱신한다. generated full design을 재생성한다.
8. independent result review 뒤 evidence를 작성하고 모든 mandatory gate 통과 시만 WP를 verified로 바꾼다.

## 실패·복구

주 설계: [docs/design/DCODE_INTEGRATION.ko.md](../../docs/design/DCODE_INTEGRATION.ko.md). 작업 데이터 원본은 [plan.json](plan.json)의 `WP06`다. 각 실행 단계는 현재 승인된 작업 사본에서 수행한다.

### 제공자 capability와 tool stream conformance

인터페이스: `CapabilityService.resolve/require; ProtocolNormalizer.validate_request/consume_fragment/finalize/project_history.`. 자세한 타입·오류·트랜잭션은 [담당 설계](../../docs/design/DCODE_INTEGRATION.ko.md)를 따른다.

1. verified/declared/unknown capability evidence를 durable runtime identity에 연결한다. model 이름으로 행동 특화 profile을 생성하지 않는다.
2. 논리 request·physical attempt·provider tool id mapping을 정의한다. 원시 stream decoder와 call assembler를 분리하고 크기·count 상한을 검사한다.
3. 종료 fragment 이전에는 완성된 JSON처럼 보여도 Broker를 호출하지 않는다. malformed/duplicate/orphan을 오류·synthetic 관측으로 보존한다.
4. 서명된 reasoning과 필수 image의 provider 전환 정책을 구현한다. lossless 변환 외는 사용자 의도 확인 또는 명시 미지원이다.
5. 실제 dcode invoke 경로·child/offload 호출에서 observer 범위를 검사한다. pure 변환 fixture와 native 통합 결과를 다른 report에 기록한다.

수용 조건: 정상 fragment는 정확히 한 번 dispatch; 불완전 call은 effect0; 서로 다른 call ID가 합쳐지지 않음; opaque reasoning 자동 텍스트 export 없음; 취소 후 usage는 기록·작업 적용은 차단.

변경 파일: `../deepagents_code/cyrano/dcode/capabilities.py`, `../deepagents_code/cyrano/dcode/normalization.py`, `../deepagents_code/cyrano/contracts/types.py`.

실제 제품 테스트는 다음 파일을 구현한 후 실행한다. 미구현/0건 수집/필수 skip은 통과가 아니다.

```bash
uv run --no-sync python -m pytest tests/cyrano_product/test_wp06_protocol.py -q
```

실행 전제: Required predecessor ports + real dcode adapter + explicit runtime cost/side-effect permit; missing prerequisites are blocked, not pass.

위험·금지: 기존 provider가 이미 normalize한 데이터를 재변환하면 서명이 깨지거나 호출이 중복될 수 있다.

## 선행 조건 판정

선행 WP는 plan.json의 `dependency_milestones`에 따라 실제 구현된 `interface_ready` 포트 evidence를 제공해야 한다. 선언이나 mock만으로 충족하지 않는다. 자신의 전체 native 수용은 `product_verified`에서 별도로 수행한다. 모든 제품 요구를 실행하지 않은 상태는 최종 출시/점수 통과가 아니다.
