## 함수·메서드 계약

- `run_work -> attempt receipt`
- `verify_artifact -> separated outcomes`
- `settle_work -> complete/blocked`
- `apply_to_target -> approved result`

각 메서드는 입력 parsing/권한/revision/snapshot 확인과 실제 처리의 소유자를 분리한다. wire field 이름은 schema를 따른다. read-only는 Scope ACL 확인 뒤 수행하고 mutation은 command→transaction→event/outbox를 사용한다. 오류 enum과 next_allowed_action을 명시한다.

## 실행 순서

1. 입력 artifact와 선행 evidence의 digest·실행 상태를 확인한다. 문서만 있는 선행 작업을 통과로 취급하지 않는다.
2. 구현 계획에 public API, 변경 경로, 불변 조건, positive/negative test, 외부 side effect, rollback을 적는다. 독립 reviewer의 mandatory finding을 먼저 해결한다.
3. 아래 acceptance ID마다 재현 가능한 거부/정상 테스트를 먼저 작성한다. 현재 기반 unit 사례를 복사해 product 통합 사례가 된 것처럼 이름만 바꾸지 않는다.
4. 명세의 결정적 부분부터 구현하고 실제 provider/host 연결은 명시 port로 결합한다. 미지원 기능은 typed unsupported로 반환한다.
5. timeout·cancel·late result·partial startup·duplicate request·scope mismatch를 포함해 구현한다. 실패를 success/empty default로 감추지 않는다.
6. 작성한 targeted test와 schema/문서/기반 회귀/품질 검사를 실행한다. 실제 runtime 또는 paid model이 필요한 부분은 별도 허가가 없으면 not_run으로 보고한다.
7. 담당 설계·schema·config·fixture·문서 라우터를 같은 변경에서 갱신한다. generated full design을 재생성한다.
8. independent result review 뒤 evidence를 작성하고 모든 mandatory gate 통과 시만 WP를 verified로 바꾼다.

## 수용 조건

- `WORK-MERGE`: merged artifact 재검증 전 complete 금지
- `WORK-UNKNOWN`: unknown outcome 보존·reconcile, blind 재실행 금지
- `WORK-SOURCE`: 원본 변경됐다고 보고 금지
- `WORK-TEST`: tamper finding으로 차단

추가 조건: API consumer가 실제 제공자에 연결되고, 잘못된 입력에 대한 실행 거부 경로가 존재해야 한다. 문서·interface만 있는 상태는 partial이다.

## 검증 명령

실행 디렉터리: monorepo의 `libs/code`. 실제 dcode 의존성 설치 후 `uv run`으로 native 통합 검사한다. 아래 기반 도구는 별도 제품 통과를 주장하지 않는다.

```sh
uv run --no-sync python -m pytest tests/cyrano_product/test_wp10_product.py -q
python cyrano/scripts/dev.py schemas
python cyrano/scripts/dev.py check
python cyrano/scripts/dev.py quality
```

첫 명령은 해당 테스트 파일을 구현한 뒤 실행한다. 현재 ZIP에는 future product test를 가짜 skip/PASS로 등록하지 않았으며 0 tests이면 명시 실패한다. quality 도구가 없으면 설치/lock 검증 후 다시 실행하고 blocked를 통과로 기록하지 않는다.

## 실패·복구

코드 변경은 허가된 개발 작업 사본 안에 보존한다. 기존 failing baseline과 신규 failure를 분리해 기록한다. 데이터 migration·원본 변경·외부 호출은 해당 approval과 복구 recipe 없이 되돌리지 않는다. unknown external outcome은 reconciliation한다. 선행 API 변경으로 실패하면 임의 fallback 대신 소유 WP와 contract를 함께 수정한다.

## 평가·native 배치 실행 계약

기존 독립 workspace 경로 대신 `libs/code/deepagents_code/cyrano/`와 native test 트리를 사용한다. pyproject/lock/native entrypoint는 이 WP의 허가 없이 덮어쓰지 않는다. 작업은 [테스트 개발 실행계획](../../docs/development/TEST_DEVELOPMENT_PLAN.ko.md)을 우선하고 모든 승인을 현재 plan digest에 결속한다.

### TS05: 승인 전 수정 차단·재검토 강제

각 실제 mode와 edit/shell/MCP/child/ACP/YOLO/resume 경로에서 무승인 mutation을 시도한다. 이벤트상의 deny뿐 아니라 inode/bytes pre-post와 외부 side effect 부재를 독립 runner가 확인한다. symlink/hardlink와 old permit CAS를 포함한다.

계약 함수: `approve_plan -> ApprovalReceipt`; `authorize_execution -> ExecutionPermit`; `validate_action_scope -> Decision`; `apply_patch_via_broker -> Snapshot`; `invalidate_on_scope_change -> Revocation`

수용 case ID는 plan.json acceptance_ids 및 tests/assessment/cases.json을 따른다. 문서·fixture 검사는 preparation이며 제품 점수는 trusted 실제 실행과 독립 review 이후에만 요청한다.

## 이 작업의 현재 읽기·구현 계약

주 설계: [docs/design/architecture/2026-09-16-runtime-security.ko.md](../../docs/design/architecture/2026-09-16-runtime-security.ko.md). 작업 데이터 원본은 [plan.json](plan.json)의 `WP10`다. 각 실행 단계는 현재 승인된 작업 사본에서 수행한다.

### MCP snapshot·선택적 ACP/A2A worker

인터페이스: `ExternalWorkerPort.submit/query/cancel; DelegationEnvelope.`. 자세한 타입·오류·트랜잭션은 [담당 설계](../../docs/design/DCODE_INTEGRATION.ko.md)를 따른다.

1. protocol/version/endpoint/executable/schema를 고정하고 declared capability와 실제 conformance를 구분한다.
2. filesystem·terminal permission callback을 Broker로 연결한다. absolute path는 승인된 workspace map에만 매핑한다.
3. submit/cancel/reconnect/late result의 ID와generation을 원장에 저장한다. peer unknown을 로컬success로 변환하지 않는다.
4. 출력 patch/artifact는 URI·size·type·archive·symlink 검사를 거친다. local trusted runner가 scope와hidden acceptance를 검증한다.
5. optional worker 미설치·인증실패·지원불가이면 명시 unavailable이고 새engine/자격증명탐색/무음fallback은 없다.

수용 조건: cancel notification은완료아님; schema drift차단; peer completed는인수아님; 권한없는원문fetch0; late비용은기록.

변경 파일: `../deepagents_code/cyrano/dcode/external_worker.py`.

소비만 하는 타 담당 인터페이스: `../deepagents_code/cyrano/dcode/adapter.py` (WP00), `../deepagents_code/cyrano/intelligence/contracts.py` (WP03). 해당 파일을 동시에 수정하지 않는다.

실제 제품 테스트는 다음 파일을 구현한 후 실행한다. 미구현/0건 수집/필수 skip은 통과가 아니다.

```bash
uv run --no-sync python -m pytest tests/cyrano_product/test_wp10_external_worker.py -q
```

실행 전제: Required predecessor ports + real dcode adapter + explicit runtime cost/side-effect permit; missing prerequisites are blocked, not pass.

위험·금지: 외부 tool 설명·AgentCard는 권한의 근거가 아니다. 실제 원격 도구 실행은 별도 동의·예산 필요.

## 선행 조건 판정

선행 WP는 plan.json의 `dependency_milestones`에 따라 실제 구현된 `interface_ready` 포트 evidence를 제공해야 한다. 선언이나 mock만으로 충족하지 않는다. 자신의 전체 native 수용은 `product_verified`에서 별도로 수행한다. 모든 제품 요구를 실행하지 않은 상태는 최종 출시/점수 통과가 아니다.
