# widgetbox module convention

Every widget module in the `widgetbox` package MUST satisfy all three of the following. This is verified against the two existing modules (`alpha.py`, `beta.py`) and the registry contract.

1. **Module-level `render() -> str`.** Each widget module defines a top-level function named exactly `render`, taking no arguments, annotated `-> str`, with a one-line docstring of the form `"""Render the <name> widget."""`.

2. **`render()` returns the widget's identifier string.** It returns the module's own name as a lowercase literal (e.g. `alpha.py` returns `"alpha"`, `beta.py` returns `"beta"`). The return value must equal the module name; it must not be derived from other modules or side effects.

3. **Registration in `registry.REGISTERED`.** Every widget module must be listed by name in the `REGISTERED` tuple in `widgetbox/registry.py` (currently `("alpha", "beta")`). `registry.py` is the single source of truth — "every widget module must be listed" — so adding a widget module requires adding its name to that tuple.

Supporting conventions (present in both modules, inferred rather than enforced by code): a module docstring of the form `"""<Name> widget."""`, and no package re-exports in `__init__.py` (it contains only the package docstring).

Summary: a compliant widget module is a single file in `widgetbox/` that (a) exposes `render() -> str` returning its own module name, and (b) is enumerated in `registry.REGISTERED`.
