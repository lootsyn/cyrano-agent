## 구현 순서

1. 담당 API의 typed 입력·출력·오류와 schema를 먼저 고정한다. Pydantic/JSON schema가 권한을 보장하지 않음을 유지한다.

2. 앞선 문서의 storage/transaction/ACL/revision/clock 규칙에 맞춰 결정적 domain 로직을 구현한다. 기존 native 코드를 대체하는 빈 loop를 만들지 않는다.

3. 아래 4개 사례 각각의 fixture builder·positive/negative assertion을 작성한다. fixture는 raw 결과를 위조하는 success stub이 아니다.

4. fault injection·idempotency·cancel·late response를 검사하고, native port adapter는 실제 dcode graph에 연결해 검증한다.

5. source/plan/review/test/trace evidence를 연결한다. protected state나 oracle을 agent가 직접 변경하지 못하도록 검증한다.

6. native 품질 검사·관련 회귀·독립 코드 리뷰 후 document catalog와 schema/fixture를 갱신한다.

## 개발·실행 명령

모든 명령 cwd는 monorepo `libs/code`다. 테스트 파일을 실제 구현한 다음 실행한다. 없거나 0개 수집이면 blocked/fail이며 skip PASS를 만들지 않는다.

```sh

uv run --no-sync pytest tests/cyrano_product/test_r4_rc01.py --collect-only -q

uv run --no-sync pytest tests/cyrano_product/test_r4_rc01.py -q --junitxml=cyrano/evidence/RC01-junit.xml

uv run --no-sync python cyrano/scripts/dev.py check

uv run --no-sync python cyrano/scripts/dev.py quality

```

Live provider가 필요한 case는 operator 허가·실행 예산·fixture manifest가 먼저다. key가 없으면 비밀을 생성하거나 평가 결과를 꾸미지 않는다. 생성될 파일과 명령이 현재 native 환경에서 지원되는지는 RC00에서 확인한다.



## 완료 기준·실패 복구

`evidence/work-packages/RC01.json`에 source/runtime/suite/policy digest, 실제 argv/exit/status, 사례별 evidence, reviewer identity, scope, known limitations를 기록한다. 모두 통과해도 상위 전체 제품을 자동 완료로 바꾸지 않는다.

DB/파일 변경 실패는 transaction·receipt에 따라 복구하고, external unknown outcome은 reconcile한다. active 사용자 workspace를 cleanup 대상으로 사용하지 않는다. 새 contract 변경은 영향 WP에 알리고 stale 승인·평가를 무효화한다.
