# 데이터·API·Schema·Migration 계약

문서 유형: 상세 설계 · 상태: 계획(제품 미구현)


## Problem

여러 워커와 UI가 같은 작업을 수정할 때 동작을 prose만으로 설명하면 revision·scope·idempotency·권한 규칙이 구현마다 달라진다. 과거 설계의 타입 이름과 새 프로젝트의 타입을 혼용하지 않도록 기계 계약과 원본 보존·migration 원칙이 필요하다.

## Proposal

### 통합 R2 wire contract

v1 단독 진실원천이라는 범위를 강화한다: contracts/contract-registry.json이 현재 canonical_sources와 target_replacements를 소유한다. 기존 v1 JSON bytes는 유지한다. 새 execution path는 GovernedWorkPlan, TrustedApprovalReceipt, ToolExecutionPermit, RunnerVerification, ExecutionChangeManifest, RunCompletionReport@2를 명시 사용한다. v2 field는 governance.schema.json이 소유한다. event payload는 event-catalog와 event-payloads schema에 따라 검증한다. v1-only consumer는 governed용으로 미지원이며 default버전 추론은 금지한다.

자세한 해석·충돌 해결은 [Universal Harness 통합 설계](2026-09-16-universal-harness-integration.ko.md)를 따른다. 원본첨부에 있는 더 느슨한예시로 이규칙을낮추지 않는다.

### 1. 계약 우선순위

이번 프로젝트의 machine field names는 `contracts/v1/cyrano.schema.json`이 소유한다. 파일 이름·타입·enum은 generated schema catalog를 참조한다. prose의 인간용 개념 이름을 새로운 JSON 필드로 추가하지 않는다. prose와 schema가 충돌하면 테스트·fixture·문서·schema를 같은 변경에서 고쳐야 하며 어느 하나를 임의 무시하지 않는다.

첨부 interview 원본 worker/approval schemas는 별도 원본 계약이다. adapter가 새 envelope를 감싼다고 내부 의미를 없애지 않는다. DREAM 원본 8개 계약은 과거 설계 reference로 보존하며 runtime의 동일 타입으로 이중 등록하지 않는다. 원본과 새 모델의 대응은 아래 semantic mapping을 사용한다.

| 이전 개념 | 신규 소유 타입/참조 | 의미 |
|---|---|---|
| interview decision bundle | InterviewContract | planning 승인용, execution_authorized=false |
| DREAM 후보 | CandidateProposal + ImpactAssessment | Author 선언과 classifier 판정 분리 |
| learning plan | LearningWorkPlan + ExperimentPlan | 개선 작업 계획과 실제 평가 설계 분리 |
| replay world/attempt | A 전용 evidence artifact | sealed evaluator/runner 소유, policy에는 공개 view만 |
| active memory | MemoryRecord + HarnessRelease component | 승인된 projection, 후보와 분리 |
| 평가결과 | EvaluationReport + actual execution refs | JSON 숫자만으로 authority 없음 |
| prompt context | ContextManifest | CYRANO 주입 범위·실제 wire 관측 구별 |

### 2. JSON validation

외부 command, model output, config, durable payload, queue, worker, file, network 경계에서 validation한다. `additionalProperties=false`로 알 수 없는 필드를 거부하고 schema_version으로 format을 구별한다. 단순 dict를 저장한 뒤 나중에 의미를 추론하지 않는다. 같은 프로세스의 잘 정의된 내부 함수는 타입을 사용하되 외부의 string ID를 typed 객체로 바꾸는 parsing 책임은 경계 소유자에게 둔다.

JSON Schema는 field 형식만 검사한다. signature authority, DB reference 존재, scope equality, current revocation, digest 내용 일치, independent review, pair count equality 같은 의미 검사는 trusted service에서 별도로 수행한다. schema-valid fixture는 실험·승인 증거가 아니다.

### 3. 공통 CommandEnvelope

`id`, `command`, `scope`, `expected_revision`, `input_digest`, `idempotency_key`, `actor_ref`, `payload_ref`, `permit_ref`를 포함한다. actor_ref는 transport 인증 identity와 일치해야 한다. payload_ref는 content-addressed artifact를 지목하고 scope ACL·실제 digest를 검사한다. 처음 생성 command도 expected_revision=0 등의 명시 규칙을 사용한다.

읽기 요청은 별도 scope-aware query API다. read-only라고 다른 tenant의 ID를 조회할 수 있는 것이 아니다. 해당 principal에게 object 존재를 알려도 되는지 검토하고 미권한 object ID를 상세 error로 노출하지 않는다. administrative 검색은 별도 허가된 endpoint에만 둔다.

### 4. 오류와 HTTP 의미

| 코드 | HTTP 예시 | retry | caller 행동 |
|---|---|---|---|
| SCHEMA_INVALID / INVALID_PATCH_PATH | 422 | false | 입력 수정 |
| UNAUTHORIZED / WRONG_PURPOSE / SCOPE_DENIED | 403 | false | trusted 권한 요청 |
| STALE_REVISION / SNAPSHOT_MISMATCH | 409 | 재조회 후 새 요청 | 현재 상태로 계획·승인 재검토 |
| IDEMPOTENCY_CONFLICT | 409 | false | 다른 payload에 key 재사용 금지 |
| BUDGET_EXHAUSTED / MISSING_REVIEW | 409 | 조건 충족 뒤 | pause 이유를 표시 |
| RUNTIME_UNVERIFIED / CAPABILITY_UNSUPPORTED | 503 | 자동 무한 retry 금지 | WP probe·지원 환경 확인 |
| UNKNOWN_OUTCOME | 202 또는409 | blind retry 금지 | reconciliation command |
| HOLDOUT_ACCESS_DENIED / EVAL_TAMPER | 403 | false | incident 검토 |
| OUT_OF_SUPPORT | 정상 평가 상태 | 실제 탐색 허가 필요 | replay score 미확정 |

`ErrorEnvelope`는 code/message/retryable/current_revision/related_ids/next_allowed_action이다. 관련 ID는 caller scope에서 공개 가능한 것만 포함한다. stack trace·credentials를 사용자 JSON에 넣지 않는다. timeout·cancel·unsupported를 모두 internal error로 뭉개지 않는다.

### 5. 목표 HTTP API

`contracts/api/openapi.json`은 개발할 CYRANO Control API의 명세이며 현재 실행 서버가 있다는 뜻이 아니다. 기본 `/v1/commands`가 typed command envelope를 받아 receipt reference와 revision을 반환한다. command registry는 허용된 이름·payload type·purpose·state precondition을 검증한다. 임의 Python 함수 이름 실행은 허용하지 않는다.

`GET /v1/streams/{stream_id}`는 scope-필터된 상태, `GET /v1/events`는 cursor 기반 authorized events, `GET /v1/artifacts/{digest}`는 scope·sensitivity 확인 후 artifact, `GET /v1/runtime/status`는 실제 health coverage를 반환한다. `POST /v1/approvals`는 별도 interactive identity와 CSRF 검증이 필요하고 agent token에 허용하지 않는다. opaque path ID로 인증을 대신하지 않는다.

### 6. 명령 registry

인터뷰: user_event.ingest, interview.propose, interview.apply_worker, interview.compile, interview.review, interview.export.
계획·실행: plan.propose, plan.review, work.reserve, work.execute, work.settle, patch.apply.
기억: memory.query(read), memory.propose, memory.review, memory.activate, memory.invalidate.
학습: learning.plan, learning.propose, learning.classify, experiment.authorize, experiment.start, experiment.settle, candidate.review.
릴리스: release.prepare, release.promote, release.rollback, release.revoke.
복구: run.cancel, outcome.reconcile, outbox.reclaim.

각 command는 `contracts/api/command-catalogue.json`의 owner/payload/purpose/precondition/failure/transaction 항목을 따른다. 아직 없는 command를 CLI stub로 만들어 성공 반환하지 않는다. 현재 offline CLI는 status/demo/test 관련 명령만 구현한다.

### 7. 저장소와 SQL

Content-addressed blob store는 immutable bytes를 저장한다. SHA mismatch면 quarantine한다. SQLite target schema는 stream revision, events, idempotency requests, outbox, artifacts, entity versions, dependency edges, scopes, approvals, releases/pointers, attempts, experiments/pairs, memory indexes를 분리한다. `contracts/sql/target-schema.sql`은 목표 DDL을 syntax/test DB에서 검증하는 명세이며 기존 Store의 운영 migration으로 자동 적용하지 않는다.

일관성 핵심은 하나의 transaction 안에 expected revision 확인, event insert, entity projection, idempotency response, 필요한 outbox를 기록하는 것이다. artifact bytes는 transaction 밖에서 temp로 준비한 뒤 digest 봉인하고, DB가 참조한 뒤 cleanup policy에 포함한다. 부분 publish나 orphan blob은 reconciliation으로 회수한다. DB transaction 중 오래 걸리는 LLM·네트워크 요청을 수행하지 않는다.

### 8. Entity version과 참조 무결성

수정은 기존 entity body overwrite가 아니라 새 version과 supersedes 관계다. event는 append-only이다. derived projection은 rebuild할 수 있지만 승인·실행 원본 event는 replay에 따라 다른 의미로 바뀌지 않는다. unknown required event kind 또는 future schema는 명시적으로 읽기를 거부한다. optional ignorable event는 문서화된 정책이 있을 때만 skip한다.

review/evaluation/approval/release는 본문 digest를 참조한다. artifact digest만 알고 있으면 누구나 읽을 수 있게 만들지 않는다. `(tenant,user,workspace)` scope index를 query에 포함하고 context cache key에도 ACL revision을 포함한다. 삭제 request는 원본/derived/index/export 영향 범위를 원장에 남긴다.

### 9. Migration 원칙

schema version은 단조 증가하며 `vN→vN+1` 인접 migration으로 관리한다. 변경은 데이터 migration, code consumers, schema/fixture, archived format reference, compatibility test를 같이 갱신한다. 기존 released generation을 덮어쓰지 않는다. source snapshot에서 가동 중인 old runtime이 새 format을 몰라도 fallback 성공처럼 읽지 않는다.

초기 foundation Store는 작은 독립 schema를 가진다. full target schema로 확장할 때 WP02는 backup·dry-run·검증·activation 절차와 이전 데이터 import mapping을 명시해야 한다. 이미 존재하는 DB에 target DDL을 무조건 실행하는 startup 코드는 금지한다. rollback 가능한 범위와 forward-only 변경을 구별한다.

### 10. Seed code와 제품 코드 구분

기반 함수들은 deterministic behavior를 실제로 실행하고 테스트한다. `evidence_ready: bool`, `input_semantics_unchanged: bool` 같은 내부 인자는 trusted caller가 검증한 전제를 전달하는 순수 함수용이다. HTTP payload에서 그 값을 읽어 authority로 사용하는 구현은 금지한다. WP03/WP16/WP20이 신뢰된 receipt→internal precondition 변환을 구현한다.

### 11. 서명·참조 순환을 피하는 subject digest

각 artifact의 full raw digest와 승인용 `binding_digest`는 서로 다르다. `contracts/v1/digest-projections.json`은 타입별로 모든 필드를 subject_fields 또는 envelope_fields에 정확히 한 번 배정한다. 새 필드를 추가할 때 projection을 갱신하지 않으면 gate가 실패한다. approval refs, signature refs, mutable status는 본문을 승인한 뒤 붙는 envelope다. 의미가 있는 scope·patch·constraint·budget·반례·기준은 반드시 subject에 포함한다.

순서는 LearningWorkPlan subject(L)→L 검토·허가→CandidateProposal subject(C, L 참조)→ImpactAssessment(C 참조)→ExperimentPlan subject(E, C 참조)→E 실험 permit→actual results/EvaluationReport→candidate/evaluation reviews→HarnessRelease subject(S)→S promotion approval/signature→published envelope다. CandidateProposal이 미래 ExperimentPlan digest를 역참조하지 않는다. 해당 필드명은 `learning_work_plan_digest`다. `artifact_digest`는 제안한 component 내용 hash이며 자기 Proposal 전체 hash가 아니다.

release의 review_refs는 이미 끝난 candidate/evaluation/code review를 가리킨다. 아직 없는 release 최종 승인 receipt를 subject 안에 넣어 순환하지 않는다. 최종 release 승인 receipt는 S를 서명하고 envelope에 붙인다. PlanBundle·InterviewContract의 리뷰/승인 refs도 동일한 본문에 대한 별도 authority evidence다. status를 바꾸어 subject hash가 그대로라도 커널 전이·권한 검사 없이 active가 될 수 없다.

wire의 `candidate_digest`, `experiment_plan_digest`, `parent_release_digest`처럼 authorization/lineage에 쓰는 digest는 해당 versioned subject digest다. blob body 무결성은 별도 full raw digest와 artifact index가 담당한다. 실제 source/patch bytes는 raw digest를 사용하고 canonical projection으로 대체하지 않는다. 승인 서명 payload는 purpose·subject digest·scope·expiry·nonce·policy도 함께 묶는다.

### 12. 인터뷰 원본 adapter의 정확한 변환

CYRANO role `evidence-scout`는 원본 `evidence_scout`, `blind-handoff-reviewer`는 `blind_reviewer`로 대응한다. Facilitator/Critic은 원본 이름을 그대로 사용한다. 원본 worker의 input_digest는 64 hex, CYRANO는 sha256 접두어를 사용하므로 알고리즘·길이를 검증한 뒤 접두어만 변환한다. 원본 status complete는 분석 완료이지 interview readiness가 아니다. WorkerOutcome은 일반 CYRANO worker용이며 원본 interview 결과를 이 타입으로 강제 축소하지 않는다.

## Alternatives considered

**모든 것을 JSON 하나에 저장:** 명시적인 state/authority/version 검사가 어려워진다. 타입별 contract와 event/projection 소유권을 둔다.

**원본 설계 contract를 모두 runtime 타입으로 중복 등록:** 이름·필드·상태가 충돌한다. 원본은 보존하고 신규 adapter mapping을 소유한다.

**마이그레이션 실패 시 옛 코드로 자동 재시작:** format 호환성이 없으면 데이터 손상이 가능하다. 검증된 복구 절차만 실행한다.

## Acceptance criteria

schema positive/negative fixtures, semantic cross-reference 검사, target DDL integrity, CAS/idempotency/outbox failure injection, unknown future format 거부, ACL query isolation, origin/CSRF와 purpose 분리, artifact tamper 검사가 통과해야 한다. generated catalog가 schema·registry 변경과 동기화돼야 한다.

## Risks

prose와 machine field 이름이 어긋나기 쉽다. 구조 목록은 generator가 만들고 edit source를 한곳으로 유지한다. contract fixture의 sample data를 운영 승인·통계 데이터로 재사용하지 않는다.

### R2 transport·payload·업무 완료의 구분

CommandEnvelope@1은 transport이고 그 payload는 명시 payload_schema_ref가 선택한 v1 또는 v2다. transport 버전을 보고 payload를 추측하지 않는다. work.settle의 RunnerVerification 제출은 검사 하나의 수신이지 전체 작업 완료가 아니다. workflow 서비스가 현재 WorkUnit의 change manifest·전체 required checks·review를 조회해 완료 여부를 계산한다. 객체 간18개 추가 의미 검증은 contracts/v2/semantic-rules.json이 소유한다.

## 1. 공통 원칙

identity는 표시 이름이 아니라 안정된 opaque ID다. `RuntimeScopeBinding`은 신뢰된 실행 context에서 주입하고 모델이 제출한 tenant/user/workspace를 그대로 믿지 않는다. `RuntimeArtifactRef`는 내용을 임의로 fetch할 URL이 아니라 승인된 blob 저장소의 참조다. body digest와 실제 bytes·size를 검사한다. secret은 모델 전달 artifact에 포함하지 않는다.

초안 wire digest는 `sha256:<64 lowercase hex>`다. **기존 canonical digest·approval subject 알고리즘을 교체하라는 뜻이 아니다.** 기존 v1/v2의 native digest format은 명시 adapter로 구분하고 승인 가능한 새 형식은 별도 버전으로 검토한다. map key order·Unicode normalization·숫자 표현은 기존 canonical contract를 준수한다. 의미가 다른 bytes를 같은 hash로 정규화하지 않는다.

모든 필드는 JSON schema에서 required이며 nullable은 명시적으로 null일 수 있다. 누락을 0/빈 목록/성공으로 보정하지 않는다. 상태가 verified이면 필요한 evidence_ref가 존재해야 하고 timestamp/dependency/authority 검사는 service가 수행한다. JSON schema 구조 통과가 의미·권한 검증은 아니다.

## 2. 모델·컨텍스트 인터페이스

```python
from collections.abc import Iterable, Mapping
from typing import Protocol

# 각 타입의 필드는 이 문서에 동봉된 contracts/v2/runtime.schema.json이 정의한다.
# ModelRequest/StreamFragment/NativeMessages는 검토된 upstream 타입이다.

class CapabilityService(Protocol):
    async def resolve(self, runtime_digest: str) -> CapabilityEnvelope: ...
    def require(self, envelope: CapabilityEnvelope,
                required_features: frozenset[str]) -> None: ...

class ProtocolNormalizer(Protocol):
    def validate_request(self, request: ModelRequest,
                         capabilities: CapabilityEnvelope) -> NormalizationRecord: ...
    def consume_fragment(self, attempt_id: str,
                         fragment: StreamFragment) -> None: ...
    def finalize(self, attempt_id: str) -> NormalizationRecord: ...
    def project_history(self, messages: NativeMessages,
                        target: CapabilityEnvelope) -> tuple[NativeMessages, NormalizationRecord]: ...
    def reconcile_missing_observation(self, call_id: str,
                                      evidence: RuntimeArtifactRef | None) -> NormalizationRecord: ...

class ContextService(Protocol):
    def compile_epoch(self, run_id: str,
                      stable_refs: tuple[RuntimeArtifactRef, ...]) -> ContextEpoch: ...
    def compact(self, epoch: ContextEpoch,
                observations: tuple[RuntimeArtifactRef, ...]) -> ContextEpoch: ...
    def record_cache_observation(self, observation: CacheObservation) -> None: ...
```

`consume_fragment`는 도구를 실행하지 않는다. `finalize`까지 유효한 종료·문자열·schema가 확인된 것만 Action Broker에 전달할 수 있다. `compact`가 실패하면 이전 epoch가 active로 유지되고 입력을 잘라서 새 epoch로 발표하지 않는다.

```python
                                evidence: EvidenceBundle) -> RuntimeArtifactRef: ...
```

`mark_application`의 반환은 referenced_only/applied/unverifiable이다. 원문 참조 없이 LLM 문장만 있으면 applied가 될 수 없다. `request_promotion`은 사람/정책 broker에 요청하는 proposal artifact만 만든다. active pointer를 바꾸는 권한은 이 agent-facing service에 없다.

## 5. 편집·외부 worker·관측 인터페이스

```python
class AnchoredEditService(Protocol):
    def validate_patch(self, anchors: tuple[PatchAnchor, ...]) -> RuntimeArtifactRef: ...
    async def apply_candidate(self, validated_patch: RuntimeArtifactRef,
                              permit: RuntimeArtifactRef) -> RuntimeArtifactRef: ...

class ExternalWorkerPort(Protocol):
    async def submit(self, envelope: DelegationEnvelope) -> str: ...
    async def query(self, external_task_id: str) -> RuntimeArtifactRef: ...
    async def cancel(self, external_task_id: str) -> str: ...

class ObservationQuery(Protocol):
    async def timeline(self, run_id: str, after_sequence: int,
                       limit: int) -> RuntimeArtifactRef: ...
    async def reconcile_effect(self, attempt_id: str) -> RuntimeArtifactRef: ...
```

validate는 source에 쓰지 않는다. apply는 검증된 effect fence 이후 candidate에만 적용한다. 원본 source 적용은 기존 Broker 별도 권한이다. external query는 외부 상태를 그대로 완료 verdict로 반환하지 않고 신뢰 등급이 external_peer인 artifact를 반환한다. timeline의 limit은 목록 제한이며 전체 aggregate를 제한하지 않는다.

## 7. 트랜잭션 규칙

**Task claim:** BEGIN IMMEDIATE → task revision/deps/permit 확인 → fencing_token 증가+lease 저장 → event+outbox 저장 → COMMIT. commit 실패 시 dispatch하지 않는다. 외부 dispatch는 outbox consumer가 수행하며 at-least-once를 전제로 effect-id/idempotency 검사를 한다.

**Memory proposal:** candidate+evidence refs+scope 저장, active는 유지한다. **Promotion:** evidence와 candidate/parent digest 검증 → 승인 receipt 확인 → active pointer expected parent CAS → event 기록. 모델 도구는 이 DB writer에 접근하지 못한다.

**Billing:** physical_attempt_id/provider_request_id unique로 normalized usage를 merge한다. unknown을 확정 0으로 대체하지 않는다. 늦은 response가 task generation과 달라도 billing row를 보존한다.

**Apply:** prepared patch+journal digest를 먼저 commit한다. 파일마다 before/after를 검사하며 적용한다. 중간 실패는 effect unknown/reconciliation required로 남긴다. 외부 여러 파일 변경을 SQLite transaction 하나로 원자화했다고 주장하지 않는다.

## 8. 오류·UI 표시

모든 오류는 code, operation_id, retryable, evidence_ref, user_action_required를 가진다. user-visible message는 redacted다. `retryable=true`는 실행 retry 권한이 아니라 해당 operation이 재시도 가능하다는 정보다. 실제 retry는 permit·budget·generation을 다시 확인한다.

오류 분류: INPUT_INVALID / CAPABILITY_UNAVAILABLE / CALL_ID_COLLISION / INCOMPLETE_TOOL_CALL / TOOL_ARGUMENT_LIMIT / OBLIGATION_LOSS / CONTEXT_BUDGET / ACL_DENIED / STALE_EVIDENCE / MEMORY_REVOKED / DAG_CYCLE / RESOURCE_CONFLICT / BUDGET_EXHAUSTED / PERMIT_STALE / LEASE_LOST / UNKNOWN_EFFECT / INDEX_STALE / PATCH_STALE / REMOTE_UNVERIFIED / AUDIT_UNAVAILABLE / MIGRATION_REQUIRED / VERSION_CONFLICT.

권한·손상·unknown을 ‘찾지 못함’으로 접지 않는다. UI에 충분한 context를 주되 secret/path scope 밖 데이터를 메시지로 유출하지 않는다.

## 현재 계약의 단일 소유권

`contracts/contract-registry.json`은 타입과 validator의 선택을 소유한다. `contracts/v1/cyrano.schema.json`은 현재 제공되는 순수 foundation의 기존 타입, `contracts/v2/governance.schema.json`은 목표 권한·세션 타입, `runtime.schema.json`은 모델·컨텍스트·작업·외부 결과 결속, `planning.schema.json`은 계획/HITL 세부 객체다. 새 날짜별 schema나 보완팩 schema는 만들지 않는다.

세션 전역 상태는 기존 v2 상태기계 하나다. planning 객체의 세부 review 상태는 세션 내 소유 객체이며 자동으로 세션 실행 허가를 만들지 않는다. `RuntimeScopeBinding`의 추가 task/ACL 필드를 포함한 객체를 기존 Scope로 자동 캐스팅하지 않는다. 원본 tenant/user/workspace와 현재 trusted context의 교집합을 검사하고 내부 adapter가 필요한 projection을 만든다.

`WorkflowIR`에는 살아 있는 permit 참조를 넣지 않는다. `WorkflowExecutionBinding`이 compile된 IR digest, plan subject digest, 허가 참조, 실행 generation을 결속한다. 컴파일 결과가 동일해도 실행 권한의 현재 유효성은 효과 직전에 다시 확인한다.

`ObservationQuery.effect_status`는 일반 UI read 권한으로 실제 재실행·복구를 호출하는 API가 아니다. 조회형 `effect_status`와 권한 있는 `request_reconciliation`을 별도 endpoint로 구현한다. 조회 화면은 unknown 상태를 읽을 뿐 효과를 재시도하지 않는다.

## 요청과 반환의 실행 규약

모든 쓰기 service는 `command_id/idempotency_key`, expected object revision, trusted caller, payload digest를 받아야 한다. 모델 prompt에서 들어온 actor/scope/producer 문자열을 인증된 caller로 사용하지 않는다. 반환은 `accepted/rejected/deferred/stale/unknown_effect`와 stable error code, 새 revision, 관련 evidence ref다. 오류 메시지는 원시 secret·다른 scope의 파일명을 담지 않는다.

workflow·monitor·memory·learning의 publisher는 같은 event store를 사용한다. R4/R5 schema의 이름이 남아 있더라도 두 번째 운영 원장이나 중복 scheduler를 만들지 않는다. 실제 deployed state가 없는 첫 구현은 목표 DDL을 빈 DB에서 검증한다. 제품 release 이후의 migration·철회·감사 의무는 유지하지만 개발 문서의 납품판 이력은 실행 입력으로 삼지 않는다.
