**1-3.4 · 1점:** 필요한 주석의 정확성·유지보수성. 사전 정의 case 전부와 이 단위의 실제 제품 증거가 있어야 한다.

## R3-13-01 — 문서화된 public API

계층: `component`. 구현 파일(CYRANO 문서 root 기준): `../tests/cyrano_product/test_1_3.py`. 함수: `test_r3_13_01`.

**Given:** 주요 함수 inventory와 Google-style role/Args/Returns/Raises fixture.

**When:** fx_13_1를 isolated candidate와 고정 trusted evaluator에 주입한 뒤 해당 기준의 공개 service를 호출한다.

**Then:** 자동 coverage와 독립 의미 리뷰가 모두 완료된다.

### 구현·실행 절차
1. 현재 source/runtime/policy/suite digest와 predeclared case list를 봉인하고 task/run/attempt ID를 발급한다.
2. 주요 함수 inventory와 Google-style role/Args/Returns/Raises fixture.
3. 호출 직전·직후 file inventory, event cursor, release pointer를 기록한다. 모델·프로세스·service의 실제 출력과 종료 상태를 수집한다.
4. 자동 coverage와 독립 의미 리뷰가 모두 완료된다.
5. outcome과 원시 로그 hash·검증 artifact를 evaluator-owned registry에 등록한다. cleanup 이후 side effect 잔존 여부를 확인한다.

### Fixture 계약

`tests.cyrano_product.fixtures.fx_13_1:build`는 sealed_repository/trusted_policy/fault_injection_spec을 받아 workspace_id/attempt_id/preimage_digest/expected_assertions/cleanup_handle을 반환한다. 이는 개발할 fixture이며 이미 구현된 helper라고 가정하지 않는다.

### 판정·증거

자동 coverage와 독립 의미 리뷰가 모두 완료된다. testcase의 expected denial이 확인되면 case 자체는 passed일 수 있지만, 거부된 제품 작업을 completed로 바꾸지 않는다. `source-manifest.json`, `run-binding.json`, `events.jsonl`, `case-result.json`, `independent-review.json`을 동일 evidence bundle로 결속한다.

### 정리·재실행

프로세스·lease·임시 root를 정리하고 알려지지 않은 외부 결과는 reconciliation; 실제 저장소는 보존. 재실행은 새 attempt로 기록하고 최초 실패를 지우지 않는다. 비용·서비스 키가 없으면 blocked이며 mock으로 대체해 live 성공을 주장하지 않는다.
