# 3-1 · Memory 저장·세션 종료 후 유지

배점: **2점**. 구현 소유: `WP11`. 제품 테스트는 모두 `not_run`이다.

## 채점 단위

**3-1.1 · 1점:** 사실·규칙·경험의 근거와 지속 저장. 사전 정의 case 전부와 이 단위의 실제 제품 증거가 있어야 한다.

**3-1.2 · 1점:** 새 프로세스·세션의 정확한 scope/freshness 복원. 사전 정의 case 전부와 이 단위의 실제 제품 증거가 있어야 한다.

## R3-31-01 — 세션 간 기억

계층: `governed_integration`. 구현 파일(CYRANO 문서 root 기준): `../tests/cyrano_product/test_3_1.py`. 함수: `test_r3_31_01`.

**Given:** 프로세스 A가 검증된 프로젝트 규칙과 episode를 저장하고 완전히 종료한다.

**When:** fx_31_1를 isolated candidate와 고정 trusted evaluator에 주입한 뒤 해당 기준의 공개 service를 호출한다.

**Then:** 프로세스 B의 새 thread에서 같은 workspace의 승인된 record를 조회할 수 있다.

### 구현·실행 절차
1. 현재 source/runtime/policy/suite digest와 predeclared case list를 봉인하고 task/run/attempt ID를 발급한다.
2. 프로세스 A가 검증된 프로젝트 규칙과 episode를 저장하고 완전히 종료한다.
3. 호출 직전·직후 file inventory, event cursor, release pointer를 기록한다. 모델·프로세스·service의 실제 출력과 종료 상태를 수집한다.
4. 프로세스 B의 새 thread에서 같은 workspace의 승인된 record를 조회할 수 있다.
5. outcome과 원시 로그 hash·검증 artifact를 evaluator-owned registry에 등록한다. cleanup 이후 side effect 잔존 여부를 확인한다.

### Fixture 계약

`tests.cyrano_product.fixtures.fx_31_1:build`는 sealed_repository/trusted_policy/fault_injection_spec을 받아 workspace_id/attempt_id/preimage_digest/expected_assertions/cleanup_handle을 반환한다. 이는 개발할 fixture이며 이미 구현된 helper라고 가정하지 않는다.

### 판정·증거

프로세스 B의 새 thread에서 같은 workspace의 승인된 record를 조회할 수 있다. testcase의 expected denial이 확인되면 case 자체는 passed일 수 있지만, 거부된 제품 작업을 completed로 바꾸지 않는다. `source-manifest.json`, `run-binding.json`, `events.jsonl`, `case-result.json`, `independent-review.json`을 동일 evidence bundle로 결속한다.

### 정리·재실행

프로세스·lease·임시 root를 정리하고 알려지지 않은 외부 결과는 reconciliation; 실제 저장소는 보존. 재실행은 새 attempt로 기록하고 최초 실패를 지우지 않는다. 비용·서비스 키가 없으면 blocked이며 mock으로 대체해 live 성공을 주장하지 않는다.
