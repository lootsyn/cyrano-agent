## R3-34-01 — 효과 개선 후보

계층: `live_dcode`. 구현 파일(CYRANO 문서 root 기준): `../tests/cyrano_product/test_3_4.py`. 함수: `test_r3_34_01`.

**Given:** predeclared baseline/candidate 실제 paired trials와 regression suite를 실행.

**When:** fx_34_1를 isolated candidate와 고정 trusted evaluator에 주입한 뒤 해당 기준의 공개 service를 호출한다.

**Then:** 품질/비열등성·비용 상한·안전 hard gate 통과 증거 뒤에만 promote 가능.

### 구현·실행 절차
1. 현재 source/runtime/policy/suite digest와 predeclared case list를 봉인하고 task/run/attempt ID를 발급한다.
2. predeclared baseline/candidate 실제 paired trials와 regression suite를 실행.
3. 호출 직전·직후 file inventory, event cursor, release pointer를 기록한다. 모델·프로세스·service의 실제 출력과 종료 상태를 수집한다.
4. 품질/비열등성·비용 상한·안전 hard gate 통과 증거 뒤에만 promote 가능.
5. outcome과 원시 로그 hash·검증 artifact를 evaluator-owned registry에 등록한다. cleanup 이후 side effect 잔존 여부를 확인한다.

### 판정·증거

품질/비열등성·비용 상한·안전 hard gate 통과 증거 뒤에만 promote 가능. testcase의 expected denial이 확인되면 case 자체는 passed일 수 있지만, 거부된 제품 작업을 completed로 바꾸지 않는다. `source-manifest.json`, `run-binding.json`, `events.jsonl`, `case-result.json`, `independent-review.json`을 동일 evidence bundle로 결속한다.

### 정리·재실행
